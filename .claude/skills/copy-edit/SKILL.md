# Copy Edit

Review the writing the user specifies and apply every rule below. For each violation found, rewrite the offending sentence or passage. Present the revised version with a brief note on what changed and why.

## Brand Context — Jarvis Helpdesk

When editing Jarvis-related copy, keep these in mind:

- **Voice**: Professional but approachable. Not corporate-stiff, not casual-sloppy.
- **Product**: AI Agent omnichannel helpdesk for Vietnamese SMBs and enterprises
- **Key terms**: Use "helpdesk" (not "help desk"), "omnichannel" (not "multi-channel"), "AI Agent" (not "AI-driven")
- **Bilingual**: Content may be in Vietnamese or English. Apply the same rules to both languages.

## Rules

1. **No em-dashes, colons, or semicolons.** Rewrite every sentence that uses one. Break into separate sentences or restructure.

2. **No negation-as-definition.** Never define something by saying what it isn't ("It's not X, it's Y"). State what it is directly.

3. **No staccato fragment sequences.** Rewrite "Short. Choppy. Sentences." into full sentences with varied structure.

4. **No dangling participial phrases.** Never extend a sentence with ", giving you...", ", allowing teams to...", ", enabling...", etc. Make it a separate sentence or cut it.

5. **Banned verbs.** Do not use any of these as action verbs: "unlock," "elevate," "streamline," "empower," "leverage," "foster," "navigate," "revolutionize," "transform," "supercharge."

6. **No "Whether you're..." or "Imagine..." openers.** Do not start sentences with scenario-setting phrases like these.

7. **No "in today's [noun]" filler.** Cut any sentence containing "in today's fast-paced world," "in today's digital landscape," or similar.

8. **No tricolon lists for emphasis.** Rewrite patterns like "Faster. Smarter. Better." or "Plan it. Build it. Ship it."

9. **No vague inspirational closers.** Cut or rewrite any section-ending or page-ending statement that is generic enough to apply to any product.

10. **No hyperbolic qualifiers.** Avoid "seamless," "cutting-edge," "next-generation," "game-changing," "revolutionary," "state-of-the-art." Use concrete descriptions instead.

## Process

1. Determine what the user wants edited. This could be a single file, a block of text they pasted, or multiple files in the repo. Ask if unclear.
2. Read the full piece (or each file) first.
3. Apply all 10 rules in a single pass.
4. Edit in place. If the user pointed to a file, edit that file directly. If they pointed to multiple files, edit each one. If they pasted text, output the cleaned version.
5. After editing, list the changes made as a summary (group by rule number if helpful).
